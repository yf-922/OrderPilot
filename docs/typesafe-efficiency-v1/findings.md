# 官方 Jev 三组线上验证结果

2026-10-17，真实主模型 gpt-6.1-sol、官方 Jev jev-1.13.0。三组使用相同两条 8 轮对话：普通跨轮订单取消、早期禁止操作约束。共 48 个用户轮次，串行交错执行，无自动重试；业务工具与 RAG 是固定 Mock，调用主模型与 Jev 均为真实请求。本次为自由运行 E2E，不是固定 Gold History 的单步回放，各组实际生成历史可能不同。

输入指标包含所有主模型调用与 Jev 调用的实际输入；规则/模型绕过主模型的轮次仍保留在平均值分母。任务成功依据后端只取消正确订单、禁止操作订单保持不变、没有提前取消以及最终 completed 状态，不靠助手自述判断。工具执行成功是后端调用成功，不能替代工具选择准确率。

## 如何理解收益

- 规则路由相对仅三级压缩，输入减少 **14.96%**，本次观测的平均响应增加 **29.61%**。
- 官方 Jev 相对规则路由，输入增加 **7.22%**，平均响应增加 **27.68%**，任务完成率未提高。
- 官方 Jev 组合相对仅三级压缩，输入减少 **8.82%**，平均响应增加 **65.49%**。不能将组合的 Token 降幅全部归因于外部 Jev。

官方 Jev 调用 5 次，实际采用 2 次，3 次因工具 Noul 判断落入不确定区而安全回退；成功返回但未采用的用量也已计入。Jev 输入 5,853 Token、输出 1,155 Token，主模型输入 64,745 Token、输出 1,385 Token。仅看主模型会误认为 Jev 相对规则又省了 1,102 输入 Token，计入外部模型后实际净增加 4,751 Token。

两个最后确认轮均由 Go 规则直通完成，R/J 组各绕过 2 个主模型用户轮；这项收益属于规则与后端令牌处理，不属于外部 Jev 的推理收益。

官方 Jev 五次调用合计约 5.094 秒，平均每次约 1.019 秒；318.38ms 是分摊到全部 16 个用户轮的均值，不能当作单次 Jev 延迟。J 组最慢的 28.820 秒发生在没有外部调用的第 5 轮，主要为主模型网络时间；不能把全部延迟差解释为 Jev 开销。C 组只有 2048 个返回的缓存输入 Token，R/J 为 0；本次没有设计冷热缓存实验，无法断言缓存是原因。

严格工具路径与参数同时正确：C=16/16，R=15/16，J=16/16。R 组第一条对话列订单后额外查询了一次订单状态，该工具本身执行成功，但不符合严格预期路径，所以工具执行成功率仍为 17/17，而严格轨迹为 15/16。三个方案跨轮指代与最终确认均为 4/4。

每组只有两条对话，不足以宣称总体准确率 100%、线上 P95 SLA 或统计显著的速度变化。当前证据支持“规则路由节约输入”，不支持“外部 Jev 已带来额外效率提升”。后续应优先优化外部触发条件，减少只因“和”字触发的同类政策问题；并研究不确定工具保守并集是否能保留已高置信的指代结果。优化需要另起版本对照，不能回改本次冻结参数或挑选性剔除慢请求。
