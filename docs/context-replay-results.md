# 客服对话上下文回放测试

## 场景与测量

这是自建模拟会话，不是线上用户记录，也未调用付费模型。8轮依次覆盖：查询两款键盘、筛选低库存、咨询配送、查询两条订单、查询订单18状态、咨询退款、申请取消18且明确不操作19、确认尚未点击按钮时订单是否取消。没有每轮100商品或人为填充的大图片字段。

对相同轨迹比较三阶段：完整历史、调用现有compactToolResult后的完整历史、调用boundedContext后的消息窗口。JSON测量统一包含system prompt、消息角色、工具调用参数/ID、工具结果和工具Schema。测量对象为内部消息与工具定义的JSON封装，不是网关HTTP请求的精确大小，也不是Token数。

| 阶段 | 字节 | 相对完整历史降幅 |
| --- | ---: | ---: |
| 完整历史 | 7355 | 0% |
| 工具字段精简 | 7162 | 2.62% |
| 字段精简与完整轮次裁剪 | 5498 | 25.25% |

历史消息由33条降至21条（包含1条system消息，最近5个完整用户轮次）。测试检查system prompt、最近用户要求不操作订单19、取消需确认、订单尚未取消，以及assistant/tool调用ID关联保持完整。

## 结论与局限

常规小结果集的字段精简收益有限，主要节省来自裁剪旧轮次。旧商品筛选条件可能被丢弃，因此不能宣称无损压缩、全历史事实保留或模型回答质量不下降。这次验证的是回放轨迹的字节体积和最近关键事实保留；未验证真实模型追问准确率、Token消耗或响应延迟。233KB到6.7KB保留为极端压力探针，简历改用本会话测试并标注模拟条件。
