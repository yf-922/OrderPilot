# 客服对话上下文回放测试

## Token 测量（同一 30 例）

使用常见 BPE 分词工具 **tiktoken 0.14.0 / cl100k_base** 对原始 JSON 字符串直接编码计数，未按字节数换算。编码器固定且可复现，未调用付费模型；该编码器不是 Grok 官方 tokenizer，不能当作 Grok 计费 usage。特殊标记按普通输入文本编码。

范围保持与字节测试一致：每例会话末尾的 `messages + tools` 完整内部 JSON 封装，包含 system prompt、消息、工具参数/ID、Observation 和工具 Schema。不是所有轮次请求的累计输入量，也不包含网关私有聊天模板或模型供应商的协议开销。工具 Schema 按内部结构计数，不是供应商转换后的精确格式。

| 阶段 | 平均 Token/会话 | 本步骤平均节省 Token |
| --- | ---: | ---: |
| 完整历史 | 1978.97 | — |
| 工具结果精简 | 1887.23 | 91.73 |
| 结构化状态 + 完整轮次裁剪 | 1598.63 | 288.60 |
| 合计节省 | — | 462.87 |

- **逐例 Token 降幅的算术平均：14.39%，简历取 14.4%。**
- **总 Token 量降幅：19.22%。** 等价于用平均体积计算 `(1978.97−1598.63)/1978.97`，不是逐例百分比平均。

原有字节统计仍保留作对照，不能把字节的 19.0% 直接写成 Token 的 19.0%。Token 实测逐例数据、分词器版本及平均值保存在 `docs/context-token-v2-report.json`。现在的裁剪流程先生成结构化会话状态，再注入状态快照和近期完整轮次；状态保存目标订单、保护订单、地址不可变、待确认订单及已由确认接口完成的动作。采用 Token 口径后推荐简历：

> **上下文管理：** 将订单号、保护约束和确认状态抽取为结构化会话状态，并结合工具结果精简与完整轮次裁剪控制多轮 Agent 上下文；在 30 个模拟客服会话回放中，基于 tiktoken 分词估算，输入 Token 数平均降低 **14.4%**，同时保留结构化业务约束与工具调用链完整性。

复现（仓库根目录）：

```powershell
python -m pip install -r tests/requirements-context.txt
python tests/context_token_eval.py
python -m unittest discover -s tests -p test_context_token_eval.py
```

脚本先运行 Go 回放测试，将真实三阶段 JSON 导出到临时目录，再编码统计；报告路径可用 `--output` 指定，默认更新报告文件。可用 `--encoding` 切换分词器，但不同编码器结果须分开标注，不可为了提高降幅挑选编码器。结构测试及历史事实保留的限制仍见下文。

## v2：30 场景回放（2026-10-06）

固定题集 `agent/testdata/context_replay_v2.json` 包含恰好 30 个自建模拟客服会话，2–12 轮，商品结果每次 0–8 条、订单 1–5 条；不是线上真实记录。五组各 6 例：短对话、商品筛选、多意图与取消确认、安全与异常、长对话（其中取消组与异常组各含多种意图切换）。具体分组以逐例表为准，不据此声称生产流量分布。

回放通过共享场景步骤生成器生成用户话术、工具调用、模拟 Observation 和答复，调用实际的 `compactToolResult` 与 `boundedContext`。测试不调用模型、不执行订单变更；“超时、拒绝、越权”等结果是预设 Observation，用于检查裁剪后信息是否保留，不能把本测试作为安全拦截率或任务完成率评测。部分恢复场景模拟用户稍后重新提问，未模拟运行时交接系统。

每例在会话末尾测量一次，不是所有模型请求的累计开销。三阶段使用相同 `messages + tools` JSON 封装，包含 system prompt、工具 Schema、工具参数/ID、答复与结果，按 UTF-8 字节计量，不是 Token 或精确网关 HTTP 请求大小。

### 平均体积与节省来源

| 阶段 | 平均字节/会话 | 该步骤平均减少字节 | 相对原始平均体积减少 |
| --- | ---: | ---: | ---: |
| 完整历史 | 7259.4 | — | — |
| 工具结果精简 | 6871.8 | 387.6 | 5.34% |
| 再做完整轮次裁剪 | 5554.9 | 1316.9 | 18.14% |
| 合计 | 5554.9 | 1704.5 | 23.48% |

工具精简主要删除商品图片 URL 与不必回喂的字段，保留商品 ID、名称、库存和错误；本套数据商品不超过 8 条，没有通过截断 100 条结果制造高降幅。政策工具精简仅去掉本套结果中的冗余 `ok` 字段，内容、来源和 found 保持不变，没有触发长片段截断。订单状态、取消确认和错误 Observation 没有做字段删除。

历史裁剪删除旧用户轮次及其 assistant/tool 消息，保留最近最多 5 个完整轮次（本套每轮 4 条消息）。平均删除 2.07 个旧轮次；system prompt 与工具 Schema 不变。节省来自消息删除而非模型摘要，无法无损保留所有历史事实。

两种统计口径：

- **逐例降幅算术平均 18.98%（简历取 19.0%）**：每例 `(原始−最终)/原始` 后平均，每个场景权重相同，简历“平均降低”建议采用这个数字。
- **平均体积之比 / 总量降幅 23.48%**：`(7259.4−5554.9)/7259.4`，等价于全部字节求和后计算；长会话权重更大。

四例完全不缩小（C01/C03/C04/C05）；各例降幅 0–48.96%。不能继续沿用单例 25.3% 作为这套 30 例的均值。

### 验证与限制

30/30 通过的是上下文结构与保留事实断言：system 完整、工具调用与 Observation ID 成对、保留窗口为完整轮次后缀、最近约束与最新答复不变、商品关键字段及政策内容/来源不变。失败 Observation 原样保留，不删除错误分类或恢复指引。本轮也补充了工具精简函数对失败结果的保留保护。不是任务完成率，不证明模型理解、无幻觉或线上安全效果。

旧历史仍可能包含以后要追问的事实。例如很早提出的商品偏好若未在最近窗口重申，可能被丢弃。尚无持久化业务记忆或摘要机制，简历应写“保留近期业务约束”，而不是“保持全部关键业务约束”。

机器可读的逐例结果见 `docs/context-replay-v2-report.json`；重建报告时设置 `CONTEXT_REPLAY_REPORT_PATH=../docs/context-replay-v2-report.json`（Go 测试从 agent 目录执行）。

## 场景与测量

这是自建模拟会话，不是线上用户记录，也未调用付费模型。8轮依次覆盖：查询两款键盘、筛选低库存、咨询配送、查询两条订单、查询订单18状态、咨询退款、申请取消18且明确不操作19、确认尚未点击按钮时订单是否取消。没有每轮100商品或人为填充的大图片字段。

对相同轨迹比较三阶段：完整历史、调用现有compactToolResult后的完整历史、调用boundedContext后的消息窗口。JSON测量统一包含system prompt、消息角色、工具调用参数/ID、工具结果和工具Schema。测量对象为内部消息与工具定义的JSON封装，不是网关HTTP请求的精确大小，也不是Token数。

| 阶段 | 字节 | 相对完整历史降幅 |
| --- | ---: | ---: |
| 完整历史 | 7355 | 0% |
| 工具字段精简 | 7162 | 2.62% |
| 字段精简与完整轮次裁剪 | 5498 | 25.25% |

历史消息由33条降至21条（包含1条system消息，最近5个完整用户轮次）。测试检查system prompt、最近用户要求不操作订单19、取消需确认、订单尚未取消，以及assistant/tool调用ID关联保持完整。

## 结论与局限

常规小结果集的字段精简收益有限，主要节省来自裁剪旧轮次。旧商品筛选条件可能被丢弃，因此不能宣称无损压缩、全历史事实保留或模型回答质量不下降。这次验证的是回放轨迹的字节体积和最近关键事实保留；未验证真实模型追问准确率、Token消耗或响应延迟。233KB到6.7KB保留为极端压力探针，简历改用本会话测试并标注模拟条件。
